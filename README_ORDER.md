# Order Agent

Run from the project directory, with Ollama serving `qwen2.5-coder:latest`:

```bash
python -m agents.order_agent --customer-id 16 "Where is order 1001?"
python -m agents.order_agent --customer-id 16 "Show all my orders"
python -m unittest -v test_database.py
python test_order_agent.py
```

The CLI customer ID simulates an authenticated session for local testing. It is
not authentication. In an application, construct the agent using only the ID
provided by the trusted login/session system:

```python
from agents.order_agent import OrderAgent

agent = OrderAgent(customer_id=session_customer_id)
result = agent.answer(customer_message)
```

The message cannot select the session identity. Qwen classifies the request and
extracts an explicit order ID as JSON. Python validates it and calls the existing
parameterized `get_order` or `get_customer_orders` helpers. Missing and foreign
orders return the same unavailable response. No SQL is generated by the model.

Qwen receives two approved responses built from authorized database records and
selects customer-friendly wording. Python accepts only an exact approved response;
any added facts, changed values, or generation failure use the deterministic
response. This deliberately limits wording flexibility to ensure factual fidelity.
Missing delivery dates are reported as missing, never estimated. Prices have no
currency label because the database has no currency field.

The result contains `answer`, authorized `orders`, `error` (technical diagnostic),
and `used_fallback`. A caller should display `answer` and keep diagnostics internal.
Extraction failures return a retry message without querying orders. The agent
does not execute cancellations, refunds, or database writes.

Tests 1–7 use real local Qwen and the existing database. Tests 8–11 inject model
errors and unsafe outputs to verify guards; these are separate from live model
checks. The tests also verify that the database contents remain unchanged.
